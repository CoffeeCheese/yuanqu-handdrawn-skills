# 输出目录

模型生成和本地代码绘图共用此保存规则。先确定本次输出根目录，再保存文件；安装目录用于读取技能资源，输出位于用户工作目录。

## 根目录

- 未指定目标目录：当前工作目录的 `output/`。
- 指定普通目标目录，如 `/Users/某人/Desktop/redBook/`：在其中建立 `output/`。
- 用户已经明确指定输出根目录，如 `./output/`、`./output/yuanqu-handdrawn/`，或指定一个目录作为输出根：直接采用，不重复追加 `output`。
- 用户明确指定某个成品文件路径时，成品遵从该路径；记录与代码仍归入选定输出根的对应子目录，并记录关联路径。

本地渲染 CLI 的 `--out-dir` 始终接收已确定的**输出根目录**，不负责猜测普通目标目录；默认值为当前工作目录的 `output`。

## 分类存放

```text
output/
├── images/                  选中的成品 PNG／JPG
├── records/                 生成指令、观察与核对记录
├── source/                  实际产生的可编辑文件或代码
└── work/                    需要保留的候选或临时文件，按任务分目录
```

按实际产物创建子目录。输出根目录只承载分类目录，成品目录只放选中图片。

- 模型生成：`images/<名称>.png` 与 `records/<名称>.generation.md`。模型没有返回绘图源码时，只保存实际图片和记录，不为凑目录构造 SVG、scene 或代码。
- 本地代码绘图：PNG／JPG 放 `images/`；`.scene.json`、`.svg` 及本次另写的绘图代码放 `source/`；`.report.json`、`.analysis.md` 放 `records/`。
- 候选图与临时数据需要留存时放 `work/<任务名>/`，记录选中的成品和候选的关系。工具已经保存的候选可在记录里引用实际路径，无需再次复制。用户原图默认只记录来源路径。

同一成品的各类文件共享一个名称，重名时统一编号，不能分别编号导致图片与记录错配。任何关联文件已有同名时，为整组选择新名称；写入采用不覆盖已有文件的方式。本地渲染 CLI 会为自己输出的整组文件预留名称；agent 添加 `.analysis.md` 时也须遵守同名关联规则。

## 记录与交付

记录成品、参考、候选和源码的真实路径。更新本地渲染报告时使用 CLI 返回的 `files`，不能按旧的平铺目录拼接路径。识别记录复制到 `records/<成品名>.analysis.md`。

聊天展示选中的成品并给出 `images/` 内的文件路径，必要时附记录链接；中间代码与临时文件不作为成品展示。仅分析／仅提示词的成果存入 `records/`。

本规则用于后续输出。整理既有目录需用户另行要求；移动已有成品时同步更新记录中的路径，不把历史引用留在旧位置。
